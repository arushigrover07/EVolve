Question 1 - Scale your application (5 marks) 
Your application's user base is about to grow sharply. Identify a realistic peak-demand situation 
for your own domain (for example, an outpatient rush in a hospital, results day at an institute, or a 
production shift change in a factory) and make your application handle it without downtime. 
a) Describe your peak-demand situation and the API that will be hit hardest. Then run three 
instances of your backend using Docker Compose behind an Nginx load balancer, connected 
to your existing cloud database. Show that requests are distributed across all three instances. 
(1 mark) 
b) Using Apache Bench or any suitable free load-testing tool (for example, hey, JMeter or 
k6), send 1,000 requests to that API, first with 1 instance and then with 3 instances, keeping 
the same tool and concurrency level for both runs. Tabulate requests per second and 
average response time, and state the improvement. (1.5 marks) 
c) Stop one instance while the load test is running and record the failed requests. Then configure 
Nginx so that no request fails, and show the before-and-after count. (1.5 marks) 
d) Draw the architecture diagram of your own implementation, using the actual names of your 
components: your frontend, the three backend containers and Nginx from part (a) (with their 
ports), your cloud database and hosting platform from Assignment 1, and the tools used (e.g., 
MongoDB Atlas, Render, Firebase). Then add the cloud bursting or edge/fog computing 
component to the same diagram, marked in a different colour, and explain how it would 
handle your peak-demand situation from part (a), and why you chose it for your domain. (1 
mark)
